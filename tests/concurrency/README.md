# 并发与时序用例

这一组用例专门盯「异步写入导致的串数据」——它不会让构建失败、也不会在类型检查里出现，
只会在特定操作顺序下悄悄写错数据，所以单独成组，不混在功能用例里。

## 为什么单独放

历史上反复出现的三类问题，都能在这里找到对应断言：

| 类 | 表现 | 覆盖文件 |
| --- | --- | --- |
| 过期写入 | 旧响应覆盖新弹窗 / 旧会话写进新账号 | `crud-shell-timing`、`account-session`、`user-session-timing`、`request-401-session` |
| 依赖未就绪 | 权限/部门/草稿还没回填就允许提交 | `crud-shell-timing`、`modeler-draft-session` |
| 幂等 | 连点导致重复提交、未读数重复扣减 | `notify-unread` |

## 写这类用例的约定

1. **用 `deferred()` 造挂起**，不要靠 `setTimeout` 赌时序；
2. **断言「最终写进去的值」**，而不是「函数被调用了几次」——调用次数对不代表数据对；
3. **先让它对新代码通过**；修改相关实现后如果变红，说明这次改动动了时序保证，需要复核；
4. 涉及弹窗的用例要覆盖**同一条记录重开**（仅比记录 ID 的守卫会在这里失败）。

## 备注

`login-redirect` 用的是真实 vue-router memory history；`request-401-session` 用的是真实
axios 拦截器；弹窗/树的用例用真实 Element Plus 组件，只有 HTTP 与展示组件用替身。
