# 前端开发规范

> 本文是**上手教程**：讲这套项目里页面怎么写、为什么这么写。示例展示当前接口用法，迁移到新业务时需要配套请求函数、VO 类型、中英文文案和后端菜单权限；含 `…` 的代码块是结构片段，不是可独立运行的完整页面。
> 硬性约束与项目索引见 `AGENTS.md`（两者冲突时以 `AGENTS.md` 为准）。
> 本次同步日期：2026-11-12；依据当前源码核对 CRUD、回填和连接生命周期约定。
>
> 建议阅读顺序：§0 → §2（先判断表格形态）→ 对应章节的示例 → §9（异步表单）→ §11 提交前自查。复用为新系统时先看 §14.5。

## 0. 开始之前

三条经验，能省掉大部分返工：

1. **能套壳就套壳** —— 列表页优先用 `UseCrudView` / `TreeCrudView`。这两套壳已经做好搜索区、分页、新增/编辑弹窗、删除确认、加载态和间距，手写一遍通常只是在重复它们（壳表达不了的结构见 §3.3）
2. **用设计令牌，不写裸值** —— 颜色、圆角、字号、间距、动效时长都有对应的 `--p-*` / `--theme-*`，换主题、切暗色时才不会漏改（§7）
3. **文案进 i18n** —— 用户可见文本放 `src/i18n/locales/`，中英两套同步改；只改一半，切到英文时会出现中英混排（§5）

这些点在 §11 有一份可逐项核对的自查表。

## 1. 目录与文件结构

```text
src/views/<domain>/<module>/
├── index.vue          # 页面
└── apis/
    ├── index.ts       # 请求函数
    └── type.ts        # 请求/响应类型
```

| 项           | 约定                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 页面目录     | 小写，多单词用短横线（`expression-config`、`notice-user`）                    |
| 组件文件     | PascalCase（`PropertyPanel.vue`、`TodoPopup.vue`）                            |
| 公共组件     | 放 `src/common/components/<Name>/index.vue`                                   |
| 组合式函数   | 放 `src/common/composables/use<Name>.ts`，导出 `use<Name>()`                  |
| 请求函数命名 | `<module>Page` / `add<Module>` / `modify<Module>ById` / `remove<Module>ByIds` |

**组件 `name` 与后端菜单的 `route_name` 保持一致（区分大小写）**，这是标签栏缓存的匹配依据：`<keep-alive :include>` 按组件 `name` 命中，写差一个大小写不会报错，只是这一页的缓存悄悄失效——切换标签时状态照常丢失，很难联想到是命名问题。

> 现状：24 个菜单页面的 `name` 已与后端 `route_name` 对齐（PascalCase，如 `Config` / `Dict` / `ApprovalTodo`），可以直接参照。
> 视图路由的 `meta.keepAlive` 由 `transformBackendRoutes` 默认置为 `true`（目录为 `false`），所以新页面把 `name` 写对就自动有缓存。
>
> 想确认缓存是否真的生效，看这条链路是否四环齐全：菜单 `route_name` = 组件 `name` → 转换层写 `meta.keepAlive` → `tags-view` 记入 `cachedViews` → `AppMain` 的 `include` 命中。

## 2. 表格形态判定

先判断这张表属于哪一类，再看对应章节——比直接照抄某个页面省事，也能避免「用错壳再改回来」。

```text
有分页查询接口（返回 { rows, total }）？
├─ 是 ──→ 普通表格   → UseCrudView + useCrud        （§3.1）
└─ 否
   └─ 数据是层级结构（children）？
      ├─ 是 ──→ 树形表格 → TreeCrudView + useTreeCrud  （§3.2）
      └─ 否 ──→ 是否只读/无增删改？
         ├─ 是 ──→ 普通表格 + readonly                （§3.1.6）
         └─ 否 ──→ 壳表达不了，先看 §3.3 再决定
```

当前分布：**22 个表格页全部走壳**——普通表格 20 个（其中 9 个 `readonly`）、树形表格 2 个（`system/dept`、`system/menu`），没有手写表格。

## 3. 表格开发规范

### 3.1 普通表格：`UseCrudView` + `useCrud`

绝大多数列表页都是这一套。壳里已经实现：搜索区、工具栏、表格容器、分页、新增/编辑弹窗、删除确认、加载态、底部间距；页面提供 `pageApi`、搜索/表单字段和必填的 `columns`。普通数据列由壳生成，自定义单元格用 `#cell-<prop>`，选择列与操作列分别放 `#table-prefix` / `#table-append`。**不存在旧的 `#table` 自写列入口。**

**标准 CRUD 页面不应再手写**卡片/分页/新增编辑弹窗，也不要重复定义列表的 `loading`、`searchData` 或 `getTableData`。业务额外弹窗放 `#extra`；关联选项的加载状态与必要的业务样式可以保留，但不要复制壳的状态和页面骨架样式。

`useCrud<Q, T>` 会把查询条件和行类型传到 `slotProps` 与壳的插槽；新增页面应显式传 VO 类型。`#cell-<prop>` 的 `row` 来自 Element Plus 插槽，仍是 `any`，字段名需要自行核对。

#### 3.1.2 `UseCrudView` 属性

| 属性                     | 类型                     | 默认                             | 说明                                                             |
| ------------------------ | ------------------------ | -------------------------------- | ---------------------------------------------------------------- |
| `slotProps`              | `UseCrudSlotProps<Q, T>` | 必填                             | 固定传 `crud.slotProps`                                          |
| `columns`                | `TableColumnDef[]`       | 必填                             | 模板传 computed 列定义；普通数据列由壳生成                       |
| `columnKey`              | `string`                 | 当前路由名                       | 覆盖列偏好的持久化键                                             |
| `submitDisabled`         | `boolean`                | 未设置（按 false 处理）          | 只禁止确定按钮和壳内提交入口，不禁止输入                         |
| `formDisabled`           | `boolean`                | 未设置（按 false 处理）          | 禁用 el-form 支持的输入控件；需同时禁止提交时也传 submitDisabled |
| `formRules`              | `FormRules`              | —                                | 新增/编辑共用校验；只读列表可不传                                |
| `addTitle` / `editTitle` | `string`                 | 自动                             | 不传则用「新增」「编辑」                                         |
| `readonly`               | `boolean`                | `false`                          | 不渲染新增/编辑弹窗                                              |
| `dialogWidth`            | `string`                 | `min(760px, calc(100vw - 32px))` | 宽表单可传 `min(860px, …)`                                       |
| `tableProps`             | `object`                 | —                                | 透传 `el-table` 属性，如 `{ border: true, height: '520px' }`     |
| `labelWidth`             | `string`                 | `168px`                          | 窄标签可传 `144px`                                               |
| `labelPosition`          | `'left'\|'right'\|'top'` | `left`                           |                                                                  |
| `hidePagination`         | `boolean`                | `false`                          | 后端无分页接口时隐藏分页区                                       |

#### 3.1.3 插槽

| 插槽             | 作用域参数                                          | 放什么                                             |
| ---------------- | --------------------------------------------------- | -------------------------------------------------- |
| `#search-form`   | 全部 slotProps，常用 `{ searchData }`               | 搜索字段（**不含**查询/重置按钮）                  |
| `#actions`       | 全部 slotProps                                      | 工具栏左侧按钮                                     |
| `#actions-right` | 全部 slotProps                                      | 工具栏右侧按钮（导出、清理）                       |
| `#table-prefix`  | 全部 slotProps                                      | 选择列；树形壳的树列也放这里                       |
| `#cell-<prop>`   | Element Plus 单元格作用域，常用 `{ row }`           | 标签、链接、开关等自定义单元格                     |
| `#table-append`  | 全部 slotProps，常用 `{ handleEdit, handleRemove }` | 固定操作列，仅放 el-table-column                   |
| `#form-fields`   | 全部 slotProps，常用 `{ formData }`                 | 弹窗表单字段                                       |
| `#dialog-banner` | 无                                                  | 回填失败提示与重试，位置在表单外，不受表单禁用影响 |
| `#empty`         | 无                                                  | 自定义空状态                                       |
| `#extra`         | 无                                                  | 页面自有弹窗、抽屉，保持页面单根节点               |

#### 3.1.4 `useCrud` 配置项

| 选项                                           | 必填 | 说明                                                  |
| ---------------------------------------------- | ---- | ----------------------------------------------------- |
| `pageApi`                                      | 是   | 分页查询，返回 ResponseVO<{ rows, total }>            |
| `addApi` / `updateApi` / `removeApi`           | —    | 只读列表不传                                          |
| `transformPayload`                             | —    | 提交前转载荷（补关联字段）                            |
| `defaultForm`                                  | —    | 新增初始值                                            |
| `defaultQuery`                                 | —    | 搜索初始值，**重置时恢复为此值**                      |
| `removeConfirmText` / `batchRemoveConfirmText` | —    | 自定义删除确认文案                                    |
| `onDialogOpen`                                 | —    | 上下文含 isAdd / form / row / session，供异步回填使用 |

删除接口按后端约定接收逗号拼接的 id 字符串：`removeApi: (ids) => removeXxxByIds(ids)`。

#### 3.1.5 对外接口只有三条路径

```ts
const crud = useCrud({ … })
crud.slotProps   // 模板：绑定给壳；动作从插槽作用域取
crud.refresh()   // 脚本：自定义动作后重新拉数据
crud.state       // 脚本：读写 formData / dialogVisible（回填联动）
```

| 路径        | 用途                 | 典型场景                                                       |
| ----------- | -------------------- | -------------------------------------------------------------- |
| `slotProps` | 模板消费             | `<UseCrudView :slotProps="crud.slotProps" :columns="columns">` |
| `refresh()` | 脚本主动刷新         | 行内状态开关、执行一次等自定义动作后                           |
| `state`     | 脚本读写弹窗内部状态 | 编辑时回填树勾选、监听 `dataScope` 变化                        |

不要通过替换返回对象上的方法来扩展行为，原因在下面这段注释里：

```ts
// 反例：替换公开动作引用来挂钩子，不是可靠的扩展方式。
// 原方法内部调用和插槽已持有的引用不会一起改变，且绕过 onDialogOpen 契约。
// 当前也不存在历史版本的 crud.methods。
const original = crud.slotProps.handleEdit
crud.slotProps.handleEdit = (row) => { … }
```

需要「编辑时做额外处理」用 `onDialogOpen`；需要「自定义删除文案」用 `removeConfirmText`。

#### 3.1.5.1 列配置（必填）

所有列表都必须传 `columns`，不是只在需要列设置时才传。不要自己引 `useTableColumns` 和设置按钮——`UseCrudView` / `TreeCrudView` 会统一生成列、处理列偏好并渲染设置入口：

```vue
<UseCrudView :slotProps="crud.slotProps" :columns="columns">
  <template #table-prefix>
    <el-table-column type="selection" width="50" align="center" />
  </template>
  <template #cell-status="{ row }">
    <el-tag>{{ getDictItem('system_status', row.status)?.label }}</el-tag>
  </template>
  <template #table-append="{ handleEdit, handleRemove }">
    <el-table-column fixed="right" :label="$t('common.action')" width="120">…</el-table-column>
  </template>
</UseCrudView>
```

```ts
import { computed } from 'vue'
import type { TableColumnDef } from '@@/composables/useTableColumns'

const columns = computed<TableColumnDef[]>(() => [
  { prop: 'username', label: $t('system.user.columns.username'), minWidth: 120 },
  { prop: 'status', label: $t('system.user.search.status'), width: 90, align: 'center' },
])
```

五条约定：

1. **列顺序、显隐、列宽都由壳管**，页面不要自己写 `v-if` 判断可见性，也不要自己放设置按钮
2. 单元格默认显示 `row[prop]`，需要标签/链接/按钮时用 `#cell-<prop>`；操作列放 `#table-append`，选择列放 `#table-prefix`
3. 列偏好按「路由名」持久化（可用 `column-key` 覆盖），所以同一页面多个列表要显式传不同的 `column-key`
4. 单元格全局省略号，生成列**默认带悬浮 tooltip**；不想显示全文的列传 `showOverflowTooltip: false`
5. 树形页（`dept` / `menu`）用法相同，但**树列必须放 `#table-prefix`**（展开箭头与缩进由第一列渲染），`columns` 里只写其余列

> `columns` 是必填项：壳内部只有「按配置生成列」一条路径，没有页面自写列的旧模式。参考 `src/views/system/user/index.vue`。

#### 3.1.6 只读列表

没有增删改的列表（日志、在线用户、消息记录）用壳 + `readonly` 最省事，手写等于把壳的骨架再抄一遍：

```vue
<UseCrudView :slotProps="crud.slotProps" :columns="columns" readonly>
  <template #search-form="{ searchData }">…</template>
  <template #actions>
    <el-button type="danger" @click="handleClean" v-permission="['system:log:clean']">
      {{ $t('system.operateLog.actions.clean') }}
    </el-button>
  </template>
  <template #table-append>
    <!-- 可选：详情、强制下线等行内动作列，普通数据列放 columns -->
  </template>
</UseCrudView>
```

```ts
const crud = useCrud({ pageApi: (q) => logPage(q), removeApi: (ids) => removeLogByIds(ids) })
```

**后端没有分页接口时**（如在线用户，一次返回全量数组），在 `pageApi` 里做一层适配，同时用
`hide-pagination` 隐藏分页区——不要为了一个页面手写整套骨架：

```ts
const crud = useCrud<{ username?: string }, OnlineUserVO>({
  pageApi: async (query) => {
    const res = await onlineUserList(query.username)
    const rows = res.data ?? []
    return { ...res, data: { rows, total: rows.length } }
  },
})
```

```vue
<UseCrudView :slotProps="crud.slotProps" :columns="columns" readonly hide-pagination>
  …
</UseCrudView>
```

只读列表的工具栏只放「批量删除 / 清空 / 全部已读」这类动作，行内只放「详情 / 强制下线 / 重投」，
属于**动作**而非新增编辑，因此不需要 `addApi` / `updateApi`。

### 3.2 树形表格：`TreeCrudView` + `useTreeCrud`

用于 **layered 数据 + 无分页**（部门、菜单）。

#### 3.2.1 最小实现

```vue
const columns = computed<TableColumnDef[]>(() => [
  { prop: 'deptCode', label: $t('system.dept.columns.deptCode') },
  { prop: 'sort', label: $t('system.dept.columns.sort'), align: 'right', width: 80 },
])

const crud = useTreeCrud<SystemDeptQueryVO, SystemDeptTreeVO>({
  treeApi: (query) => deptTreeList(query),
  addApi: (data) => addDept(data),
  updateApi: (data) => modifyDeptById(data),
  removeApi: (id) => removeDeptById(id as number),
  defaultForm: () => ({ status: '0', sort: 0 }),
  removeConfirmText: (row) => $t('system.dept.messages.deleteConfirm', { deptName: row?.deptName }),
  removeGuard: (row) =>
    row?.children?.length ? $t('system.dept.messages.hasChildren') : undefined,
})

// 普通 useCrud 在 onMounted 自动加载；useTreeCrud 需要页面主动发起初次加载。
void crud.refresh()
</script>
```

#### 3.2.2 与普通表格的差异

| 项           | `useCrud`                     | `useTreeCrud`                                      |
| ------------ | ----------------------------- | -------------------------------------------------- |
| 数据接口     | `pageApi` → `{ rows, total }` | `treeApi` → 完整数组                               |
| 分页         | 有                            | 无                                                 |
| 新增子级     | —                             | `handleAddChild(row)`，可用 `childForm` 定制默认值 |
| 删除         | `removeApi(ids)` 逗号拼接     | `removeApi(id)` 单条                               |
| 删除前置校验 | —                             | `removeGuard(row)` 返回文案则拦截                  |
| 展开/收起    | —                             | 壳已内置按钮，页面里不用再写                       |
| 行点击       | `@row-click` 透传             | 壳内置「点整行展开子节点」                         |

#### 3.2.3 `TreeCrudView` 属性

| 属性                                                                                                                                                               | 默认      | 说明                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------- | ---------------------------- |
| `slotProps`                                                                                                                                                        | 必填      | `UseTreeCrudSlotProps<Q, T>` |
| `columns` / `columnKey` / `formRules` / `addTitle` / `editTitle` / `readonly` / `dialogWidth` / `labelWidth` / `labelPosition` / `submitDisabled` / `formDisabled` | 同 §3.1.2 | 公共属性；树列不放 columns   |
| `rowKey`                                                                                                                                                           | `id`      | 树表主键字段                 |
| `defaultExpanded`                                                                                                                                                  | `false`   | 初始是否全部展开             |

树形壳与普通壳使用相同的 `#table-prefix` / `#cell-<prop>` / `#table-append` / `#dialog-banner` / `#extra` 插槽。`tableProps` / `hidePagination` 是普通壳专用属性，不要传给树形壳。

#### 3.2.4 容易踩的坑

- 页面里不用再写「展开全部/收起全部」按钮——壳已经渲染，文案走 `common.expandAll` / `common.collapseAll`
- 父级选择直接用 `#form-fields` 作用域里的 `treeData`，另发一次请求容易和后端树不同步
- 子级默认值有业务规则时用 `childForm(parent)`（参考菜单：目录下加菜单、菜单下加按钮）

### 3.3 壳覆盖不到的场景

项目里 22 个表格页已经全部走壳。这一节保留给**将来真遇到壳表达不了的结构**时参考；如果你觉得某个页面非手写不可，先对照下面两张表，多数情况其实能用壳解决。

**先排除这三种「以为不能用、其实能用」的情况：**

| 情况                                               | 正确做法                                           |
| -------------------------------------------------- | -------------------------------------------------- |
| 没有新增/编辑（日志、消息、审批记录、代码生成表）  | `readonly`（§3.1.6）                               |
| 操作是审批、生成、导出、撤销这类**动作**而非增删改 | 动作按钮放 `#actions` 或行内，弹窗放 `#extra` 插槽 |
| 后端没有分页接口                                   | `hide-pagination` + `pageApi` 里做适配（§3.1.6）   |

排除之后仍然做不到的，通常是这几种结构：

| 结构                                 | 为什么壳接不住                                        |
| ------------------------------------ | ----------------------------------------------------- |
| 一页里有多个互相独立的列表           | 主从双表（上表选中 → 下表联动，且两者都要自己的分页） |
| 表格内嵌可编辑单元格                 | 点击单元格原地编辑，不弹窗                            |
| 非分页语义                           | 无限滚动、游标翻页                                    |
| 页面骨架不是「搜索 + 工具栏 + 表格」 | 看板、树 + 详情双栏                                   |

真遇到时，至少沿用同一套骨架，否则间距和加载态会和列表页对不上：

#### 3.3.1 沿用页面骨架类

壳内部渲染的四个类，手写时用同名类即可，不要再写一份样式（否则两套规则会互相覆盖）：

```vue
<div class="app-container">
  <el-card shadow="never" class="search-wrapper">…</el-card>
  <el-card shadow="never">
    <div class="toolbar-wrapper">…</div>
    <div v-table-loading="loading" class="table-wrapper">
      <el-table :data="rows">…</el-table>
    </div>
    <div class="page-wrapper">
      <el-pagination … />
    </div>
  </el-card>
</div>
```

这四个类的样式由 `src/common/assets/styles/page-scaffold.scss` 统一提供：`.search-wrapper`（下间距）、`.toolbar-wrapper`（左右分布 + 下间距）、`.table-wrapper`（下间距）、`.page-wrapper`（右对齐分页）。这四个类不要在页面 `<style>` 里重复定义。

#### 3.3.2 表格视觉参考（与壳保持一致）

见 §4，与普通表格完全一致（对齐、表头换行、列宽、操作列）。

#### 3.3.3 其余同等要求

| 项             | 要求                                                      |
| -------------- | --------------------------------------------------------- |
| 加载态         | 用 `v-table-loading`（不用 `v-loading`，全站统一这一套）  |
| 删除确认       | `ElMessageBox.confirm` + i18n 文案                        |
| 权限           | `v-permission` + 后端 `@PreAuthorize` + 菜单 SQL 三处同名 |
| 搜索区字段宽度 | 用 `search-field*` 档位类，内联 `style="width"` 会被覆盖  |
| 弹窗           | `.adaptive-form` + `el-col` 布局                          |
| i18n / 令牌    | 同普通页面                                                |

## 4. 表格视觉规范（三种形态通用）

### 4.1 对齐

| 列类型                         | 写法                                         |
| ------------------------------ | -------------------------------------------- |
| 文本（名称、编码、备注、路径） | **不写 `align`**（默认左对齐）               |
| 数值（排序、数量、金额）       | `align="right"`                              |
| 时间                           | `align="center"`                             |
| 状态 / 类型（`el-tag`）        | `align="center"` + 定宽                      |
| 操作列                         | `fixed="right"` + `align="center"`           |
| 勾选列                         | `type="selection" width="50" align="center"` |

文本列建议左对齐：居中会让每行起始位置参差，纵向扫读变慢。

### 4.2 超长内容

| 位置                                 | 行为                      | 说明                                                                                                          |
| ------------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| columns 生成的数据列（含 cell 插槽） | 桌面端单行截断 + 悬浮提示 | TableColumns 显式默认开启 tooltip；关闭时在列定义设 showOverflowTooltip: false                                |
| prefix / append 手写列               | 按列属性与包装规则        | 非功能列、非 fixed 且无默认插槽的文本列会自动开启；树列需要提示时建议显式加 show-overflow-tooltip；操作列不加 |
| 表头                                 | **换行，不截断**          | Element Plus 的 tooltip 只作用于单元格，表头无 tooltip；表头是静态标签，换行即可完整可读，也不依赖 hover      |

因此**列名可以放心写长**，不需要为了塞下英文而缩短文案。

### 4.3 列宽

| 场景                         | 写法                                          |
| ---------------------------- | --------------------------------------------- |
| 文本列                       | `min-width="160"`（可拉伸）                   |
| 定宽短列（状态、排序、时间） | `width="80"` ~ `"170"`                        |
| 操作列                       | 2 个按钮 `width="90"`；4 个按钮 `width="150"` |

列宽用 `min-width` / `width` 属性，内联 `style` 容易被 EP 的样式覆盖。

### 4.4 表格属性

普通壳的 `border` / `height` 等通过 `:table-props` 传入（若将来有手写表格，直接写在 `el-table` 上）。`#table-prefix` / `#table-append` 只放固定列，不再包一层 `el-table`；普通数据列写入 `columns`，不要使用已移除的 `#table` 插槽。

## 5. i18n 规范

### 5.1 双文件同步

`src/i18n/locales/<domain>/<module>.ts` 里 `zh` 与 `en` 的 key 保持一致：漏 key 时 vue-i18n 会回退成 key 本身，界面上直接露出 `system.user.title` 这样的字面量。

### 5.2 key 分层

```ts
export const zh = {
  actions: { add: '新增', exportTitle: '导出' },
  columns: { name: '名称', status: '状态' },
  dialogs: { add: '新增示例', edit: '编辑示例' },
  form: { name: '名称', remark: '备注' },
  formPlaceholder: { name: '请输入名称' },
  messages: { deleteConfirm: '确认删除 {name}？', batchDeleteConfirm: '正在删除 {count} 条数据' },
  search: { name: '名称', status: '状态' },
}
```

| 分组              | 用途         |
| ----------------- | ------------ |
| `search`          | 搜索区标签   |
| `columns`         | 表头         |
| `form`            | 弹窗表单标签 |
| `formPlaceholder` | placeholder  |
| `dialogs`         | 弹窗标题     |
| `actions`         | 按钮         |
| `messages`        | 提示/确认    |

文案统一走 `t()`，包括 `ElMessage.warning('只能上传一个文件')` 这类提示——它同样会被英文用户看到。

### 5.3 动态引用

部分 key 不出现在 `t('…')` 字面量里：配置对象 + `t(item.labelKey)`、三元 `t(a ? 'x' : 'y')`、模板字符串 ``t(`a.${type}`)``。删文案前先确认没有间接引用。

### 5.4 校验

当前 `vite.config.ts` 未接入全量文案 key / 占位符一致性校验；构建通过不等于文案正确。提交前需要人工检查：

1. 新增文案后左右切换一次中英文，确认没有显示成 key 原文、也没有中文残留
2. 检查同一个 key 在中英两个对象里都存在
3. 含占位符（`{name}` / `{count}`）的文案，中英占位符保持一致
4. 模板插值写成 `{{ $t('x') }}`；写成单花括号 `{ $t('x') }` 会被当纯文本原样显示，而构建与 `vue-tsc` 都不会报错

## 6. 权限规范

同一个操作权限在三处保持同名，缺一处都会出现「按钮能点但接口 403」或「有权限却看不到按钮」：

| 位置   | 写法                                                    | 缺失后果                         |
| ------ | ------------------------------------------------------- | -------------------------------- |
| 前端   | `v-permission="['system:demo:add']"`                    | 无权限用户仍可见按钮             |
| 后端   | `@PreAuthorize("@ss.hasPermission('system:demo:add')")` | 接口裸奔                         |
| 菜单表 | `system_menu` 插一条 `menu_type='F'` 记录               | **按钮消失**（指令直接移除元素） |

前端指令行为：`permissions` 含 `*:*:*` 或匹配项才保留元素，否则 `parentNode.removeChild(el)`。**权限标识写错的表现是按钮凭空消失，不是点击 403。**

新增权限时，应在**配套后端仓库**的迁移目录补可重复执行的菜单/权限脚本，并验证已有环境能升级。本前端仓库不包含后端 Controller 或 `doc/sql/migration/`，不要把后端迁移路径误当成本仓库目录。前端指令只控制展示，后端仍必须执行授权检查。

## 7. 样式与主题规范

### 7.1 令牌优先

| 类型 | 令牌                                                               |
| ---- | ------------------------------------------------------------------ |
| 颜色 | `--theme-*`（文字/背景/边框/强调/功能色）                          |
| 圆角 | `--p-radius-xs/sm/md/lg/xl/2xl/full`                               |
| 字号 | `--p-text-xs/sm/base/md/lg/xl/2xl/3xl/display`                     |
| 间距 | `--p-space-0-5/1/1-5/2/2-5/3/3-5/4/4-5/5/6/7/8/10/12`              |
| 动效 | `--p-duration-fast/normal/slow`、`--p-ease-out`、`--p-ease-in-out` |
| 阴影 | `--theme-shadow-sm/md/lg/xl`                                       |

新增页面的颜色、圆角、字号、间距与动效优先使用现有令牌；不要把历史抽样比例当作当前全库审计结果，也不要因为旧代码有裸值就继续增加裸值。

### 7.2 强调色的三种用法

| 场景                       | 令牌                                        |
| -------------------------- | ------------------------------------------- |
| 强调色**当文字**           | `--theme-accent-strong`                     |
| 强调色**当图标/装饰**      | `--theme-accent`                            |
| 强调色**当填充**（配文字） | `--theme-accent-fill` + `--theme-accent-on` |

不要用装饰用途的 `accent` 替代文字用途的 `accent-strong`；具体对比度随主题和背景变化，需要在实际配色下验证。

### 7.3 暗色

全部走令牌后切一次主题检查。注意卡片面层 `--theme-bg-surface` 与浮层 `--theme-bg-elevated` 不要混用；暗色下阴影几乎不可见，需要层次时用边框或 `--theme-card-highlight`。

### 7.4 移动端

全局已处理：单元格两行截断、表头换行、工具栏换行、分页居中、搜索项独占一行、弹窗内边距收紧，页面里不用再处理一遍。

特殊需求用断点 mixin（档位定义在 `src/common/assets/styles/breakpoints.scss`）。**需要断点的样式文件自己引入**，路径按相对位置写：

```scss
@use '../breakpoints.scss' as *;   // 路径按文件位置调整

@include sm { … }      // ≤768
@include phone { … }   // ≤576
@include xs { … }      // ≤480
@include mobile { … }  // ≤991
```

> 早先这些 mixin 由 `vite.config.ts` 的 `additionalData` 全局注入，不需要 import。
> 但隐式依赖有两个毛病：文件里看不出 mixin 从哪来；一旦某次编译没带上注入
> （Vite 配置重建窗口、直接用 sass CLI 或 IDE 编译）就报 `Undefined mixin`，而报错指向业务文件。
> 现在改成显式 `@use`，任何工具都能单独编译。

### 7.5 搜索区字段宽度

用档位类，不要内联 `style="width"`（内联会被 EP 的搜索项样式覆盖）：

| 类                | 宽度  |
| ----------------- | ----- |
| `search-field-sm` | 130px |
| `search-field`    | 150px |
| `search-field-md` | 180px |
| `search-field-lg` | 200px |
| `search-field-xl` | 220px |

原因：`el-select` / `el-input` 自带 `width: var(--el-*-width)`，与单类选择器同权重且 EP 样式后加载，会把宽度覆盖成 100%。全局已用 `html` 前缀提权。

## 8. 加载态规范

| 场景                             | 用什么                                                          |
| -------------------------------- | --------------------------------------------------------------- |
| 正在加载、没有旧数据、且非失败态 | 两类 CRUD 壳内置 Skeleton，variant="table"                      |
| 换页 / 搜索 / 刷新且已有数据     | 壳内置 v-table-loading，保留旧表格，不整块替换成骨架            |
| 列表加载失败                     | tableError / treeError 驱动持久提示与重试；失败时隐藏普通壳分页 |
| 其他页面首屏整块无数据           | 按页面结构用 Skeleton，如审批详情的 variant="page"              |

列表刷新加载态用 `v-table-loading` 而不是自行叠加 `v-loading`。它带状态播报，颜色走主题令牌。两类壳共用 `useLatestRequest()`：只有最新请求且作用域未销毁时才能更新数据、错误和 loading，旧请求返回不能清掉新请求的加载态。

骨架屏用法：

```vue
<Skeleton :loading="loading" variant="table" :rows="8" :columns="6">
  <el-table :data="rows">…</el-table>
</Skeleton>
```

`variant` 支持 `page` / `card` / `table` / `list`；`delay` 默认 180ms，接口更快时完全不闪骨架。

## 9. 表单与弹窗规范

| 项           | 要求                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| 字段布局     | 壳的 `#form-fields` 外层已有 `el-row`，每个字段包一层 `el-col`（`:span="12"` 半宽 / `:span="24"` 整行） |
| 窄屏降级     | `.adaptive-form` 已处理断点，页面里不用再写                                                             |
| 校验规则     | 通过 `formRules` 传给壳；动态规则用 `computed`                                                          |
| 额外弹窗     | 详情抽屉、生成器等等放壳的 **`#extra` 插槽**，不要塞进 `#form-fields`，也**不要放在壳的同级**           |
| 弹窗内写表单 | 模板里用 `#form-fields` 的 `formData`；脚本里用 `crud.state.formData.value`                             |

### 9.1 弹窗会话与提交保护

`useCrudDialog` 是两类壳共享的弹窗状态与会话号来源。打开、关闭、销毁会使旧操作失效；异步回填用 `onDialogOpen` 中的 `session` 和 `crud.state.isCurrentSession(session)`，**不要自己再造会话计数器，也不要只比较记录 ID**（同一条记录可以被重新打开）。

`FormDialog` 的校验/提交锁和逻辑层的提交锁均按会话划分：同一会话连点不重复提交；关闭重开后新会话不继承旧请求的 loading；旧请求结束只释放自己的锁。改公共提交行为时同时核对 `useCrudDialog.ts`、`crudShell/FormDialog.vue` 和两个壳的接线。

### 9.2 关联数据回填：全部就绪才允许保存

角色、岗位、通知等页面需要「取依赖 → 应用历史关联数据 → 就绪后保存」，使用 `useEditHydration`，不要让多个分支各自修改同一个 ready 布尔值。

下面是**接线片段**：`crud` 的 `onDialogOpen` 在用户打开弹窗时才执行，所以可引用 setup 中随后初始化的 `hydration`。任务必须在首次打开前完成登记；`getDetailById` / `modifyRecord` 是业务页自己的请求函数。

```ts
import { computed } from 'vue'
import { useEditHydration } from '@@/composables/useEditHydration'

const crud = useCrud<QueryVO, RecordVO>({
  pageApi,
  addApi,
  updateApi: (payload) => {
    // UI 的 submitDisabled 不保护脚本直调入口，写入接口处也要拦截。
    if (!hydration.ready.value) return Promise.reject(new Error('form data not ready'))
    return modifyRecord(payload)
  },
  onDialogOpen: ({ session }) => hydration.start(session),
})
const isEditing = computed(() => crud.state.formData.value.id != null)
const hydration = useEditHydration({
  isCurrentSession: (session) => crud.state.isCurrentSession(session),
  isVisible: () => crud.state.dialogVisible.value,
})
hydration.register('detail', async ({ isCurrent }) => {
  const form = crud.state.formData.value
  if (form.id == null) return true
  const { data } = await getDetailById(form.id)
  if (!isCurrent()) return false
  Object.assign(form, data)
  return true
})
```

```vue
<UseCrudView
  :slotProps="crud.slotProps"
  :columns="columns"
  :submit-disabled="!hydration.ready.value && isEditing"
  :form-disabled="!hydration.ready.value && isEditing"
>
  <template #dialog-banner>
    <el-alert v-if="hydration.error.value" :closable="false" type="error">
      <template #title>
        {{ $t('common.messages.loadFailed') }}
        <el-button link type="primary" @click="hydration.retry()">
          {{ $t('common.retry') }}
        </el-button>
      </template>
    </el-alert>
  </template>
  <!-- search-form / form-fields 等见 §3.1 -->
</UseCrudView>
```

关键规则：

- 每次 `await` 后，在写表单、勾选树节点或返回成功前重新检查 `isCurrent()`；抛错或显式返回 `false` 记为失败。
- `ready` 表示所有登记步骤已满足；`runOnStart: false` 的步骤初始为 `skipped`，不阻塞就绪，**但不代表执行过**，必须确实由其他步骤负责相应依赖。
- `retry()` 按登记顺序串行补跑未成功步骤（包括 skipped），已成功步骤不重跑；中途切会话立即终止旧重试。需要重新获取源数据时通过 `resetSources` 调 loader.reset()。
- 依赖变化用 `restart(key)`，期间就绪状态回落。每个步骤只清理自己负责的数据，不要在菜单回填中顺便清空已成功回填的部门权限。
- 整体覆盖表单的回填必须同时禁用输入与提交。`formDisabled` 是 el-form 的禁用能力，不是全容器遮罩；独立树、自定义按钮等控件是否响应需显式核验。
- `stop()` 可在显式结束会话时作废在途结果；不要只直接改 dialogVisible 而绕过壳的关闭动作。
- 是否阻止新增必须由业务决定：不依赖历史数据的新增可不拦；新增也依赖树/选项的页面，需要在新增提交入口单独保护，岗位页可作为参考。

### 9.3 幂等懒加载：先成功，再回填

依赖数据首次使用才加载、并发只发一次、失败可重试时统一用 `createLazyLoader`。它不替代会话守卫，也不会自动撤销 loader 内已经进行的数据写入。

```ts
import { nextTick } from 'vue'
import { createLazyLoader } from '@@/composables/useLazyResource'

const treeLoader = createLazyLoader(async () => {
  const { data } = await loadTree()
  treeData.value = data ?? []
  await nextTick() // 放在 loader 内，让 ensure 返回时树节点已渲染
})
// 以下放在 hydration.register 的任务里：
const ok = await treeLoader.ensure()
if (!ok || !isCurrent()) return false
// 再应用当前会话的历史勾选 ID。
```

### 9.4 文件上传的持久化引用

使用 `src/common/apis/file.ts` 的 `uploadFile`（POST /file/upload，长超时 60s）。写入业务表的是 **objectKey**；`previewUrl` 是临时预签名地址，不可作为头像/附件的长期引用。上传结果回填同样需要核对当前记录/会话，不能把旧上传写进新弹窗。

## 12. 常见错误：现象与原因

1. **`v-loading`** —— 用 `v-table-loading`
2. **`el-dropdown` 默认插槽里套 `el-tooltip`** —— EP 用 `ElOnlyChild` 取触发元素，套一层组件后点击失效；触发元素用原生元素，提示改用 `title`
3. **给搜索框写内联宽度** —— 会被 EP 样式覆盖，改用 `search-field*` 档位类
4. **自己实现 `resetSearch`** —— `resetFields()` 只处理声明 `prop` 的字段，未声明 `prop` 的条件会残留；用壳的 `resetSearch()`
5. **为不存在的后端接口写页面** —— 先确认 Controller 有对应 `@RequestMapping`
6. **`v-permission` 用了没人种的权限标识** —— 表现是按钮消失而非报错
7. **页面根节点自己加 `.app-container`** —— 壳内部已有，会双倍内边距
8. **继续使用旧 `#table` 自写列模式** —— 改成必填 `columns`；固定列放 `#table-prefix` / `#table-append`，这两个插槽中也不要再包 `el-table`
9. **组件 `name` 与路由 `name` 大小写不一致** —— keep-alive 匹配区分大小写，缓存会静默失效
10. **在壳的同级再放弹窗、抽屉** —— 会让页面变成多根节点（fragment），而 `<transition mode="out-in">` + `<keep-alive>` 要求单一元素根：进入动画挂不上、`class` 也无法继承，**表现是右侧内容区直接空白**，构建与 `vue-tsc` 都不报错。把页面自有弹窗放进壳的 `#extra` 插槽即可——这类问题只能靠现象反推，所以单独列在这里
11. **在 `<keep-alive>` / `<transition>` 里用 `v-if` / `v-else` 放多个分支** —— 两者都要求**恰好一个**子节点。Vue 校验发生在**运行时**，`pnpm build:dev` 不会报错，只在浏览器里抛 `<KeepAlive> expects exactly one child component`。需要分支时把判断提到外层（如 `v-else-if` 与 `router-view` 并列），或让 `:is` 指向一个兜底组件
12. **patch 壳返回对象上的方法**（`crud.methods.handleEdit = …`）—— 用 `onDialogOpen` / `removeConfirmText` 等显式配置项，patch 既不生效也破坏契约
13. **提交被更高优先级覆盖的"无效样式"** —— 例如给 `type="primary"` 的按钮写 `--el-button-bg-color`，会被 `html .el-button--primary` 压制
14. **setup 中静态求值列名 t()** —— 切语言后表头不更新，列定义用 computed
15. **只用记录 ID 判定异步回填** —— 同一记录重开仍会串数据，使用壳的弹窗会话号
16. **仅禁用确定按钮却允许整体回填前编辑** —— 输入可能被迟到详情覆盖；同时传 formDisabled，并核验自定义控件的禁用行为
17. **把 previewUrl 写入业务表** —— 临时签名过期后图片失效；持久化 objectKey

### 图标怎么加

直接用 `<Icon icon="lucide:xxx" />` 即可，**不需要在任何地方登记**：构建期的 `vite/icon-subset.ts` 会扫描源码里的图标名，只把用到的打进包。

## 14. 开发环境说明

### 14.1 依赖预构建（optimizeDeps）

`unplugin-vue-components` / `unplugin-auto-import` 是在**转换期**才注入
`element-plus/es/components/<x>/style/css` 这类 import 的，它们不参与 Vite 启动期的依赖扫描。

结果就是「第一次打开用到某个组件的页面」时，Vite 把它当新依赖去预构建并强制刷新：

```
✨ new dependencies optimized: .../components/upload/style/css
✨ optimized dependencies changed. reloading
```

这次重载会让正在加载的模块返回 `504 (Outdated Optimize Dep)`，动态 import 失败 →
路由启动失败 → `index.html` 里的 `#app-loading` 永远不被替换 → **整个应用卡在 loading 页**。

因此 `vite.config.ts` 里用 `elementPlusStyleDeps()` 把 Element Plus **全部组件样式目录**
声明为预构建依赖（`optimizeDeps.include`）。不要改成「按用量推导」——会漏掉
`ElMessage` / `ElMessageBox` / `ElNotification` 这类由 API 调用而非标签引入的样式。

改动 `vite.config.ts` 后需要重启 `pnpm dev`，配置不会热更新。

### 14.2 改了 vite 配置或依赖后的标准动作

先停止原开发服务器，再强制重新预构建，无需手动删除目录：

```bash
pnpm dev --force
```

确认页面已恢复后，后续正常启动仍用 `pnpm dev`。

这是一套与配套后端协作的项目底座，不是任意换后端后只改名称就能完整运行的通用脚手架。沿用后端协议时优先复制为独立项目，再完成以下初始化；不要在尚未验证依赖关系前批量删除业务目录。

## 15. 实时通信与 BPMN 生命周期

### 15.1 WebSocket 的两层归属保护

业务通过 `useWebSocket` 订阅/发送，底层 `WebSocketClient` 管连接、心跳、退避重连与可见性恢复。修改时维持以下约定：

- 跨客户端替换：关闭旧客户端后不继续上报外部状态，`useWebSocket` 只接受当前客户端的状态回调。
- 同一客户端换 socket：先解绑并关闭旧 socket、清理旧定时器；open / message / close / error 回调都检查 `this.ws === socket`，旧事件不能干扰新连接。
- `1000` / `1008` / `4001` 终止性关闭，不自动重连，并设置 terminalClosed，避免 visibilitychange 绕过终止判断。
- 当前协议用 token 查询参数认证、PING/PONG 心跳和 `{ action, from, data }` 消息信封；新后端必须兼容或适配。
- 业务监听在所属页面/布局结束时解除；聊天状态只驻留内存，布局卸载调用 destroy 清理，不跨账号继承。

回归参考 `tests/webSocket.spec.ts`、`tests/websocket-status.spec.ts`、`tests/websocket-reconnect.spec.ts`；迟到事件测试应明确区分同步关闭与延迟派发路径。

### 15.2 BPMN 草稿与画布保护

`bpmn-types.ts` 只声明项目实际使用的表面。取服务用 `getService('canvas')` 等按 ServiceMap 推导的写法，不用 `modeler.get<any>(...)` 绕过类型；增加能力时先补对应类型声明。

草稿外壳 `src/views/bpm/modeler/index.vue` 负责保存与导入编排：

- 异步保存前快照 modelId、draftSessionId、元数据和编辑修订号，避免 A 的 XML 与 B 的名称混成同一载荷。
- 保存响应接管当前草稿前同时比较记录 ID 和草稿会话号；两个新建会话的 modelId 都可能为空，仅比 ID 不够。
- 服务端回读 XML 只有在原会话、编辑修订和内容仍一致时才允许排队导入，不能覆盖保存期间的新编辑。
- XML 导入走既有串行队列，不另起一条绕过守卫的导入路径。
- 发布必须建立在本次保存成功的结果上，切换草稿后不能发布错误的模型。

回归参考 `tests/concurrency/modeler-draft-session.spec.ts`；至少覆盖不同 ID 切换、同空 ID 的新建会话切换，以及保存/回读期间继续编辑。
